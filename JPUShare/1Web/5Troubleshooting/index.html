문제 해결

문제가 생기면 먼저 화면의 오류 문구와 작업 상태를 확인합니다. 같은 요청을 반복하기 전에 아래에서 해당 항목을 찾습니다.

1. 가입·로그인·연구실 참가

증상·코드확인할 내용
인증 메일이 오지 않음스팸함을 확인하고 로그인 화면에서 인증 메일을 다시 요청합니다.
세션 만료 또는 로그인 필요다시 로그인을 누르고 원래 화면으로 돌아갑니다.
계정 정보 미비참가 화면의 계정 관리 링크에서 부족한 항목(예: 학번 형식)을 고친 뒤 다시 신청합니다.
코드가 맞지 않음 (LAB_CODE_INVALID)책임교수 또는 연구실 관리자에게 받은 참가 코드가 맞는지 확인합니다. 코드를 재발급하면 이전 코드는 무효가 되므로 최신 코드를 다시 받습니다.
재시도 대기 시간 표시여러 번 틀리면 잠시 신청이 막힙니다. 표시된 시간이 지난 뒤 신청합니다.
승인 대기 중신청이 접수된 상태입니다. 책임교수 또는 연구실 관리자의 승인을 기다립니다. 책임교수가 아직 없는 연구실이면 플랫폼 관리자가 승인합니다.
연구실 소속 없음참가 신청과 승인 여부를 확인합니다.

가입 절차는 시작하기를 참고하세요.

2. 데이터가 올라가지 않을 때

오류 문구·코드확인할 내용
저장소 키 없음 (STORAGE_UNAVAILABLE)연구실 저장 공간이 준비되었는지 담당자에게 확인합니다.
할당량 초과 (QUOTA_EXCEEDED)남은 저장 용량을 확인하고, 필요한 파일을 백업한 뒤 불필요한 파일을 정리하거나 할당량을 문의합니다.
업로드 상한 초과 (UPLOAD_TOO_LARGE)파일 크기를 확인하고 나눠 준비합니다.
이름 형식 오류 (INVALID_KEY)파일·폴더 이름과 경로를 확인합니다. .. 같은 표현은 뺍니다.
동시 업로드 상한 (UPLOAD_LIMIT)진행 중인 업로드가 끝난 뒤 다시 시도합니다.
연결 끊김·대기 시간 초과목록을 새로고침해 파일이 올라갔는지 먼저 확인합니다.

업로드 위치와 입력 연결은 데이터 관리를 참고하세요.

3. 작업을 제출할 수 없을 때

제출 화면에서 표시된 칸부터 고칩니다. 오류가 여러 개면 나머지 항목도 확인합니다.

오류 문구·코드확인할 내용
이 GPU에서 돌지 않는 실행 환경 (WORKSPACE_GPU_INCOMPATIBLE)고른 실행 환경이 그 GPU 서버의 GPU 세대를 지원하지 않습니다. 화면에서는 이런 환경을 선택할 수 없지만, API로 내면 이 오류가 납니다. 다른 실행 환경이나 다른 GPU 서버를 고릅니다.
그 GPU 서버에 실행 계정이 아직 없음 (WORKER_ACCOUNT_MISSING)가입 직후 계정 준비가 일부 GPU 서버에서 끝나지 않은 상태입니다. 다른 GPU 서버를 고르거나 잠시 뒤 다시 제출하고, 계속되면 담당자에게 알립니다.
시간 제한 오류1~72시간 사이의 정수를 적습니다.
ZIP 또는 Git 주소 필요 / 둘 중 하나만코드를 ZIP과 Git 중 한 가지로 지정합니다.
실행 파일 없음 (ENTRYPOINT_NOT_FOUND)실행 명령이 가리키는 파일이 ZIP 또는 저장소 안에 있는지 확인합니다.
HTTPS 주소만 / 허용 밖 호스트HTTPS Git 주소이고 허용된 호스트인지 확인합니다.
주소에 자격 증명 포함Git 주소에 넣은 계정·토큰을 뺍니다.
ZIP 형식·경로·해제 용량 오류정상 ZIP인지, 불필요한 대용량 파일이나 잘못된 경로가 없는지 확인합니다.
저장 공간 부족 (SCRATCH_EXCEEDED)입력 크기 합계와 고른 GPU 서버의 여유 공간을 비교합니다.
실행 환경 없음 (SNAPSHOT_NOT_FOUND)실행 환경 목록을 새로고침하고 다시 고릅니다.
작업 설명 필수 / 최대 500자작업 목적을 500자 이내로 적습니다.

제출 방법은 학습 작업 실행을 참고하세요.

4. 대기하거나 실행에 실패할 때

대기 중은 실패가 아닙니다. GPU 서버는 모든 연구실이 함께 쓰므로 다른 연구실의 작업과 함께 순서를 기다립니다. 오래 이어지면 모니터에서 대기 순서를 보고, 작업 ID와 대기 시작 시각을 담당자에게 전달합니다. 실패로 끝난 작업은 상세 화면의 실패 사유 한 줄과 로그의 오류 출력을 먼저 봅니다.

작업 상태확인할 내용
실행 오류오류 출력(stderr)의 첫 오류와 실행 명령·입력 경로를 확인합니다. 실패 사유에 종료 코드가 나옵니다.
실행 환경 오류실패 사유를 확인합니다. 저장소 접근 자격 전달·코드 업로드·입력 데이터 준비 중 어디서 실패했는지 적혀 있습니다. 반복되면 작업 ID를 담당자에게 전달합니다.
제출 실패제출 내용을 확인하고, 반복되면 담당자에게 문의합니다.
GPU 메모리 부족배치 크기·입력 크기를 줄이거나 메모리가 더 큰 GPU 서버를 고릅니다.
GPU 메모리 부족(의심)로그로 실제 원인을 확인합니다.
시간 초과진행 상황과 시간 제한을 비교해 다음 실행의 시간 제한을 조정합니다.
결과 회수 실패작업 ID를 담당자에게 전달해 회수할 수 있는지 확인합니다.

5. 로그·결과가 보이지 않거나 다운로드가 안 될 때

증상확인할 내용
로그 연결 한도같은 작업을 연 다른 창을 닫고 다시 시도합니다.
결과 목록을 불러오지 못함다시 조회를 누릅니다.
결과 파일 없음코드가 /output 아래에 썼는지 확인합니다. 준비 단계에서 실패한 작업(실행 환경 오류)은 결과가 없을 수 있으니 실패 사유를 봅니다.
결과 저장소 준비 안 됨연구실 결과 저장 공간이 준비되었는지 담당자에게 확인합니다.
임시 다운로드 주소 만료목록에서 다시 다운로드를 누릅니다.
파일이 없음삭제되었거나 보관 기간(작업이 끝나고 30일)이 지났는지 확인합니다.
결과 묶음 용량 초과ZIP 전체 받기 대신 필요한 파일을 하나씩 받습니다.

6. API 오류

API 키로 호출할 때의 오류 코드와 대응은 API 사용법의 오류 코드 절을 참고하세요.

7. 해결되지 않으면

담당자에게 발생 시각, 사용한 화면 또는 API 경로, 작업 ID, 상태, 실패 사유와 오류 코드를 전달합니다. API 응답에 request_id가 있으면 함께 전달합니다.

화면이나 로그를 첨부할 때는 비밀번호·로그인 토큰·API 키·다운로드 주소와 개인정보를 가리세요.
