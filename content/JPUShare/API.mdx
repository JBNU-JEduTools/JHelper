JPUShare API의 기본 주소는 `https://share.jedutools.io`입니다. 먼저 [시작하기](/JPUShare/1GettingStarted)에서 로그인과 연구실 소속을 확인하세요.
스크립트·자동화 에이전트로 작업 제출부터 결과 받기까지 자동화하려면 [에이전트 API 가이드](/JPUShare/7AgentApi)를 함께 보세요.

### 1. 인증 방식 구분하기

| 구분 | 인증 값 | 쓰는 곳 |
| --- | --- | --- |
| 로그인 토큰(JWT) | 브라우저 로그인 때 로그인 서버가 발급 | 웹 화면. 키 관리·관리자·연구실 가입 경로는 이 토큰만 받습니다. |
| 사용자 API 키 | `jpk_`로 시작하는 키. **내 정보/설정 → API 키 발급**에서 직접 발급 | 터미널·스크립트·에이전트. 허용 범위 안의 경로만 호출합니다. |

요청 헤더는 둘 다 `Authorization: Bearer 인증값`입니다. 브라우저 로그인만으로 터미널에 토큰이 설정되지는 않으며, 비밀번호로 토큰을 받는 CLI 절차도 없습니다. **터미널에서는 `jpk_` 키를 씁니다.**

> 토큰과 API 키는 비밀번호처럼 보관하세요. 소스 코드, 공유 문서, 오류 문의에 원문을 넣지 마세요.

### 2. API 키 발급과 허용 범위

1. 로그인 후 왼쪽 위의 **내 정보/설정**을 엽니다.
2. **API 키 발급** 판에 키 이름과 유효 기간(1~90일, 기본 30일)을 적습니다.
3. **API 키 허용 범위**에서 필요한 범위만 고르고 **발급**을 누릅니다.
4. 한 번만 표시되는 `jpk_...` 원문을 안전한 곳에 저장합니다.

활성 키는 사용자당 최대 5개입니다. 범위는 발급 후 바꿀 수 없으므로 부족하면 새로 발급합니다. 키 발급·목록·폐기(`POST/GET/DELETE /v1/api-keys`)는 로그인 토큰 전용이라 `jpk_` 키로는 부를 수 없습니다.

| 범위 | 할 수 있는 일 |
| --- | --- |
| `account:read` | 내 계정·소속 정보 조회 |
| `platform:read` | GPU 서버·실행 환경·플랫폼 통계 조회 |
| `jobs:read` | 내 작업 목록·상세·로그·결과 조회 |
| `jobs:submit` | 작업 제출 |
| `jobs:cancel` | 내 작업 취소 |
| `queue:read` | 내 대기열 조회 |
| `queue:reorder` | 내 대기열 순서 변경 |
| `storage:read` | 파일 목록 조회·다운로드 주소 발급 |
| `storage:write` | 파일 업로드·폴더 생성·복사 |
| `storage:organize` | 파일·폴더 이동·이름 변경 |
| `storage:delete` | 파일·폴더 삭제 |
| `lab:read` | 소속 연구실·구성원·사용량 조회 |

범위별 경로 목록은 [에이전트 API 가이드](/JPUShare/7AgentApi)의 2절에 있습니다. 연구실 소속이 없는 계정은 `account:read`만 발급할 수 있습니다.

예제는 Bash 기준이며 `JPUSHARE_API_KEY`, `JOB_ID`는 본인의 유효한 값으로 설정한 환경 변수라고 가정합니다.

<!-- doc-exec: C01 expect=200 -->

```bash
curl --fail-with-body 'https://share.jedutools.io/v1/me' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

응답의 `username`, `lab`으로 키가 누구의 것인지, `actions`로 이 키로 할 수 있는 동작을 확인합니다.

### 3. 내 작업 조회하기

```bash
curl --fail-with-body --get 'https://share.jedutools.io/v1/jobs' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY" \
  --data-urlencode 'limit=20'
```

응답 예시의 ID와 내용은 설명용입니다.

```json
{
  "items": [
    {
      "job_id": "00000000-0000-4000-8000-000000000001",
      "state": "RUNNING",
      "priority": "NORMAL",
      "name": "학습 실험",
      "work_type": "training",
      "description": "작은 데이터로 학습 확인"
    }
  ],
  "next_cursor": null
}
```

`GET /v1/jobs`는 자신의 작업을 반환합니다. `limit`은 1~100이며 기본값은 20입니다. `state=RUNNING`처럼 상태 코드로 필터링할 수 있습니다. `next_cursor`가 문자열이면 다음 요청의 `cursor`에 그대로 전달하고, `null`이면 마지막 페이지입니다.

화면의 **대기 중**은 API에서 `USER_QUEUE_WAIT`, `GLOBAL_QUEUE_WAIT`, `ESCALATION_WAIT`로 구분됩니다. **배정됨**은 `ASSIGNED`입니다. 끝난 작업의 상태 목록과 실패 사유 필드(`last_error_code`, `last_error_message`)는 [에이전트 API 가이드](/JPUShare/7AgentApi)의 5절을 참고하세요.

```bash
curl --fail-with-body "https://share.jedutools.io/v1/jobs/$JOB_ID" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

상세 응답에는 `job_id`, `state`, `command`, `args`, `timeout_seconds`, `tier`, `attempts`, `events` 등이 포함됩니다. 제출 절차는 [학습 작업 실행](/JPUShare/3Jobs)을 참고하세요.

### 4. 데이터·로그·결과 조회하기

| 메서드와 경로 | 주요 입력 | 응답 |
| --- | --- | --- |
| `GET /v1/storage` | 없음 | `quota_gb`, `used_gb`, 자리별 사용량 |
| `GET /v1/storage/objects` | 필수 `scope`·`folder`, 선택 `prefix`, `limit`, `cursor` | `items`, `next_cursor` |
| `GET /v1/jobs/{job_id}/log` | `stream=stdout` 또는 `stderr`, 선택 `lines` | `stream`, `state`, `finished`, `lines` |
| `GET /v1/jobs/{job_id}/results` | 선택 `limit`, `cursor` | `objects`, `next_cursor`, `retention_days` 등 |
| `GET /v1/jobs/{job_id}/results-zip` | 없음 | ZIP 파일 |

저장 공간 위치는 실제 저장소 이름 대신 `scope`와 `folder` 조합으로 지정합니다.

| 화면 이름 | `scope` | `folder` |
| --- | --- | --- |
| 연구실 공유 / data | `shared` | `data` |
| 연구실 공유 / result | `shared` | `result` |
| 내 폴더 / data | `private` | `data` |
| 내 폴더 / result | `private` | `result` |

```bash
curl --fail-with-body --get 'https://share.jedutools.io/v1/storage/objects' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY" \
  --data-urlencode 'scope=shared' \
  --data-urlencode 'folder=data' \
  --data-urlencode 'prefix=train/'
```

`items`의 각 항목은 `key`, `size`, `last_modified`, `is_prefix`를 가집니다. `is_prefix=true`이면 폴더 항목입니다. 객체 `size`는 바이트, 저장 공간 용량의 `_gb` 필드는 GiB(1024³바이트) 기준입니다.

```bash
curl --fail-with-body "https://share.jedutools.io/v1/jobs/$JOB_ID/log?stream=stderr" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

로그 응답의 `lines`는 문자열 배열입니다. 아직 실행을 시작하지 않은 작업은 404 `NO_ATTEMPT`입니다. 실시간 로그는 `follow=1`을 붙이면 JSON 대신 `text/event-stream`(SSE)으로 전달됩니다.

<!-- doc-exec: C10 expect=200 -->

```bash
curl --fail-with-body "https://share.jedutools.io/v1/jobs/$JOB_ID/results" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

결과 `objects`의 각 항목은 `key`, `size`, `last_modified`, `url`, `expires_at`을 가집니다. `url`은 만료되는 임시 다운로드 주소입니다. 만료되면 결과 목록을 다시 조회해 새 주소를 받으세요. **내 폴더**로 낸 작업의 결과는 끝난 뒤 30일이 지나면 정리됩니다.

파일 업로드는 [데이터 관리](/JPUShare/2Datasets)(화면)와 [에이전트 API 가이드](/JPUShare/7AgentApi)의 4절(API), 결과 보관과 다운로드는 [결과 확인과 다운로드](/JPUShare/4Results)를 참고하세요.

### 5. 오류와 API 문서 확인

일반 오류는 `code`, `error`, `message`와 경우에 따라 `request_id`를 포함합니다. 작업 제출 검증 오류는 별도 형식인 `status: "VALIDATION_FAILED"`, `stage`, `errors`를 사용합니다. HTTP 상태도 함께 확인하세요.

| 응답 | 의미 |
| --- | --- |
| 401 | 토큰·키가 없거나 만료·폐기되었습니다. |
| 403 `JWT_REQUIRED` | `jpk_` 키로 부를 수 없는 경로입니다. |
| 403 `API_KEY_SCOPE_REQUIRED` | 키에 그 경로의 허용 범위가 없습니다. |
| 429 | 요청이 너무 잦습니다. `Retry-After` 헤더만큼 기다립니다. |

키 관리 경로를 키로 부르면 이렇게 거절됩니다.

<!-- doc-exec: C12 expect=403 -->

```bash
curl -sS 'https://share.jedutools.io/v1/api-keys' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

LLM API는 현재 제공하지 않습니다.

`/docs`, `/redoc`, `/openapi.json`은 API 문서 공개가 설정된 환경에서만 열립니다. 이 주소의 404만으로 서비스 장애라고 판단하지 마세요.

인증 오류, 요청 제한, 결과 다운로드 오류는 [문제 해결](/JPUShare/6Troubleshooting)을 참고하세요.
