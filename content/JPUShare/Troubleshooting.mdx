문제가 생기면 **화면의 오류 문구와 작업 상태를 먼저 확인**하세요. 같은 요청을 반복하기 전에 아래 항목에서 확인할 내용을 찾습니다.

### 1. 로그인·연구실 가입

| 증상 | 확인할 내용 |
| --- | --- |
| 세션 만료 또는 로그인 필요 | **다시 로그인**을 누르고 원래 작업 화면으로 돌아갑니다. |
| 계정 정보 미비 | 가입 화면의 **계정 관리**에서 학번·학과 등 부족한 항목을 확인한 뒤 다시 신청합니다. |
| 코드가 맞지 않음 | 책임교수에게 받은 연구실 가입 코드가 맞는지 확인합니다. |
| 승인 대기 중 | 신청이 접수된 상태입니다. 책임교수의 승인을 기다립니다. |
| 연구실 소속 없음 | 연구실 가입과 승인 여부를 확인합니다. |
| 사용자 등록 충돌 | 재시도로 해결되지 않으면 담당자에게 화면 문구와 발생 시각을 전달합니다. |

가입 절차는 [시작하기](/JPUShare/1GettingStarted)를 참고하세요. 책임교수만 가능한 기능이나 다른 사용자의 자료는 로그인 상태여도 접근이 제한될 수 있습니다.

### 2. 데이터가 올라가지 않을 때

| 오류 문구·코드 | 확인할 내용 |
| --- | --- |
| 저장소 키 없음 (`STORAGE_UNAVAILABLE`) | 연구실 저장소가 준비되었는지 담당자에게 확인합니다. |
| 할당량 초과 (`QUOTA_EXCEEDED`) | 남은 저장 용량을 확인합니다. 불필요한 파일은 필요한 백업을 마친 뒤 정리하거나 할당량을 문의합니다. |
| 업로드 상한 64 GiB 초과 (`UPLOAD_TOO_LARGE`) | 파일 크기를 확인하고, 데이터를 사용할 코드에 맞게 나눠 준비합니다. |
| `results/` 아래는 업로드 불가 (`RESERVED_PREFIX`) | 결과용 경로가 아닌 데이터 업로드 경로를 선택합니다. |
| 이름 형식 오류 (`INVALID_KEY`) | 파일·폴더 이름과 경로를 확인합니다. 상위 경로로 이동하는 `..` 같은 표현은 제거합니다. |
| 동시 업로드 상한 (`UPLOAD_LIMIT`) | 진행 중인 업로드가 끝난 뒤 다시 시도합니다. |
| 연결 끊김·업로드 대기 시간 초과 | 연결을 확인한 뒤 목록을 새로고침해 파일이 올라갔는지 먼저 확인합니다. |

업로드 위치와 작업 입력 연결 방법은 [데이터 준비](/JPUShare/2Datasets)를 참고하세요.

### 3. 작업을 제출할 수 없을 때

제출 화면에서 표시된 필드부터 수정합니다. 여러 오류가 있으면 첫 번째 오류 외의 항목도 확인하세요.

| 오류 문구·코드 | 확인할 내용 |
| --- | --- |
| ZIP 또는 Git 주소 필요 / 둘 중 하나만 | 코드 원본을 ZIP과 Git 중 한 가지 방식으로 지정합니다. |
| 실행 파일 없음 (`ENTRYPOINT_NOT_FOUND`) | 실행 명령이 가리키는 파일이 ZIP 또는 저장소 안의 실제 경로에 있는지 확인합니다. |
| HTTPS 주소만 / 허용 밖 호스트 | HTTPS Git 주소를 사용하고 서비스에서 허용하는 저장소 호스트인지 확인합니다. |
| 주소에 자격 증명 포함 | Git URL에 넣은 계정·토큰을 제거합니다. |
| ZIP 형식·경로·해제 용량 오류 | 정상 ZIP인지 확인하고 불필요한 대용량 파일과 잘못된 경로를 제거합니다. |
| 저장 공간 부족 (`SCRATCH_EXCEEDED`) | 선택한 tier의 작업 저장 공간과 입력 데이터·예약 용량을 확인합니다. |
| 지금 고를 수 없는 tier | 화면에서 현재 선택 가능한 tier를 확인합니다. |
| 작업 설명 필수 / 최대 500자 | 작업 목적을 500자 이내로 입력합니다. |

제출 방법은 [작업 실행](/JPUShare/3Jobs)을 참고하세요.

### 4. 대기하거나 실행에 실패할 때

**대기 중**은 실행 실패가 아닙니다. 작업 상태와 대기열을 확인하고, 오래 지속되면 작업 ID와 대기 시작 시각을 담당자에게 전달하세요. 같은 작업을 반복 제출하면 별도 작업이 생길 수 있습니다.

| 작업 상태 | 확인할 내용 |
| --- | --- |
| 배정됨 | 실행 준비가 진행되는 상태입니다. 상태 변화와 로그를 확인합니다. |
| 실행 오류 | 오류 로그(`stderr`)에서 첫 오류와 실행 명령·입력 경로를 확인합니다. |
| 실행 환경 오류 | 선택한 환경과 코드가 요구하는 라이브러리·버전이 맞는지 확인합니다. |
| 제출 실패 | 제출 내용과 작업 상세의 기록을 확인하고, 반복되면 담당자에게 문의합니다. |
| GPU 메모리 부족 | 배치 크기·입력 크기 등 메모리 사용 설정을 줄이거나 적합한 tier를 검토합니다. |
| GPU 메모리 부족(의심) | 로그로 실제 원인을 확인합니다. 상태 이름만으로 메모리 부족을 확정하지 않습니다. |
| 시간 초과 | 설정한 실행 시간과 진행 상황을 비교한 뒤 다음 실행의 시간 제한을 조정합니다. |
| 취소 중 | 취소 요청이 처리 중입니다. **취소됨**으로 바뀌었는지 확인합니다. |
| 결과 회수 실패 (`UPLOAD_FAILED`) | 실행 결과의 저장에 문제가 생긴 상태입니다. 작업 ID를 담당자에게 전달해 회수 가능 여부를 확인합니다. |

### 5. 로그·결과가 보이지 않거나 다운로드가 안 될 때

| 증상 | 확인할 내용 |
| --- | --- |
| 아직 시작 전 (`NO_ATTEMPT`) | 작업 실행이 시작된 뒤 로그를 다시 확인합니다. |
| 로그 연결 한도 (`LOG_STREAM_LIMIT`) | 다른 창의 실시간 로그 연결을 닫고 다시 시도합니다. |
| 결과 없음 (`NO_RESULTS`) | 작업 상태와 코드의 결과 저장 위치를 확인합니다. |
| 결과 저장소 준비 안 됨 (`RESULTS_UNAVAILABLE`) | 연구실 결과 저장소 준비 여부를 담당자에게 확인합니다. |
| 임시 다운로드 주소 만료 | 결과 목록을 새로고침해 새 주소로 받습니다. |
| 객체 없음 또는 다운로드 404 | 목록을 다시 조회합니다. 파일이 삭제되었거나 보존기간이 지났는지 확인합니다. |
| 대용량 받기는 Edge 또는 Chrome 필요 | 안내된 브라우저에서 다시 받고 파일 저장 위치를 선택합니다. |
| 결과 묶음 용량 초과 (`RESULTS_TOO_LARGE`) | ZIP 전체 받기 대신 결과 목록에서 필요한 파일을 개별로 받습니다. |

임시 주소의 만료와 파일의 삭제는 다릅니다. 파일이 삭제된 경우 새 주소를 받아도 복구되지 않습니다. 결과 보관은 [결과 확인](/JPUShare/4Results)을 참고하세요.

### 6. API·LLM 오류

| 응답 | 확인할 내용 |
| --- | --- |
| 401 | JWT, `jpk_` 키 또는 LLM 키의 만료·폐기 여부와 `Authorization: Bearer ...` 형식을 확인합니다. |
| 403 | 해당 작업·저장소에 접근할 권한이 있는지 확인합니다. LLM 키는 일반 API에 사용할 수 없습니다. |
| 403 `JWT_REQUIRED` | `jpk_` 키로 호출할 수 없는 경로입니다. 키 관리·관리자·LLM 경로는 로그인 JWT가 필요합니다. |
| 403 `API_KEY_SCOPE_REQUIRED` | `jpk_` 키에 그 경로의 허용 범위가 없습니다. 필요한 범위를 포함해 키를 다시 발급받습니다. |
| 400·422 | 필수 입력, 자료형, 범위와 응답의 `code`, `errors`, `detail`을 확인합니다. |
| 429 | 요청 빈도나 동시 연결을 줄입니다. 응답에 재시도 대기 시간이 있으면 그 시간을 따릅니다. |
| 503·`SERVICE_MAINTENANCE` | 점검 안내를 확인하고 종료 후 다시 시도합니다. |
| 503·`LLM_DISABLED` | LLM 서비스가 설정되지 않은 상태입니다. 담당자에게 제공 여부를 확인합니다. |
| 503·`litellm_unavailable` | LLM 게이트웨이 연결 문제입니다. 잠시 후 재시도하고 지속되면 문의합니다. |
| `/docs` 또는 `/openapi.json`의 404 | API 문서 공개가 꺼진 환경일 수 있습니다. |

LLM 키는 생성 시에만 원문을 확인할 수 있습니다. 분실·만료된 키는 JWT를 사용하는 키 관리 절차로 교체해야 합니다. 요청 예제와 인증 범위는 [API 사용법](/JPUShare/5API)을 참고하세요.

### 7. 해결되지 않으면

담당자에게 발생 시각, 사용한 화면 또는 API 경로, 작업 ID, 작업 상태, 오류 문구·코드를 전달하세요. API 응답에 `request_id` 또는 `X-Request-Id`가 있으면 함께 전달하면 도움이 됩니다.

로그와 화면을 첨부할 때는 비밀번호·JWT·API 키·임시 다운로드 주소와 개인정보를 가리세요. [JPUShare 안내](/JPUShare)로 돌아가 이용 절차를 다시 확인할 수 있습니다.
