스크립트, CI, 자동화 에이전트처럼 **브라우저 로그인 없이** JPUShare API를 호출해야 할 때는 사용자 API 키(`jpk_`로 시작)를 사용합니다. 이 문서는 키 발급부터 작업 제출·조회·결과 회수까지 에이전트가 따라 할 절차를 설명합니다.

API 기본 주소는 `https://share.jedutools.io`이며, 모든 요청은 `Authorization: Bearer <키>` 헤더를 사용합니다.

> `jpk_` 키는 발급한 사용자 본인의 자격 증명입니다. 키를 가진 에이전트는 그 사용자로 인증되며, 키의 허용 범위(scope)는 그 사용자의 권한을 **좁힐 뿐 넓히지 않습니다**. 소스 코드·프롬프트·로그·공유 문서에 키 원문을 넣지 마세요.

## 1. API 키 발급받기

키 발급과 관리는 브라우저 로그인이 필요합니다. 에이전트가 키를 스스로 만들 수는 없으므로, 사용할 계정으로 로그인해 발급한 뒤 에이전트에 전달합니다.

1. [JPUShare](https://share.jedutools.io)에 로그인합니다.
2. 왼쪽 메뉴의 **내 정보/설정**을 엽니다.
3. **API 키** 패널에서 키 이름과 유효 기간(1~90일, 기본 30일)을 입력합니다.
4. **키 허용 범위**에서 에이전트가 필요로 하는 범위만 선택합니다.
5. **키 허용 범위 확인**을 거쳐 **발급**을 누릅니다.
6. 발급 응답에 표시되는 `jpk_...` 원문을 즉시 안전한 곳에 저장합니다. 원문은 이 화면에서 한 번만 보입니다.

활성 키는 사용자당 최대 5개입니다. 키를 잃어버렸거나 노출했다면 같은 패널의 **API 키 폐기**로 폐기하고 새로 발급하세요. 폐기·만료·계정 비활성화·연구실 역할 변경은 다음 요청부터 바로 적용됩니다.

### 허용 범위(scope) 선택

범위는 에이전트가 할 일에 필요한 것만 고릅니다. 선택할 수 있는 범위는 발급자의 권한에 따라 달라집니다 — 연구실 소속이 없는 계정은 `account:read`만 위임할 수 있고, 연구실 구성원은 아래 범위 전체를 위임할 수 있습니다.

| 범위 | 에이전트가 할 수 있는 일 |
| --- | --- |
| `account:read` | 내 계정·소속 정보 조회 (`/v1/me`) |
| `platform:read` | tier·워커·실행 환경·플랫폼 통계·대기열 스냅샷 조회 |
| `jobs:read` | 내 작업 목록·상세·로그·GPU 사용량·결과 조회 |
| `jobs:submit` | 작업 제출 |
| `jobs:cancel` | 내 작업 취소 |
| `queue:read` | 내 대기열 조회 |
| `queue:reorder` | 내 대기열 순서 변경 |
| `storage:read` | 저장소 파일 목록 조회·다운로드 주소 발급 |
| `storage:write` | 파일 업로드·폴더 생성·복사 |
| `storage:organize` | 파일·폴더 이동·이름 변경 |
| `storage:delete` | 파일·폴더 삭제 |
| `lab:read` | 소속 연구실·구성원·연구실 작업·사용량 조회 |

읽기 전용 에이전트라면 `jobs:submit`·`storage:write` 같은 쓰기 범위는 빼는 것이 안전합니다.

## 2. 키로 호출하기

발급받은 키를 환경 변수에 넣고 모든 요청에 Bearer로 붙입니다.

```bash
export JPUSHARE_API_KEY='jpk_...'
curl --fail-with-body 'https://share.jedutools.io/v1/me' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

`GET /v1/me`는 키와 계정이 유효한지 확인하는 가장 간단한 호출입니다. 응답에는 `sub`, `username`, `lab`, `membership` 등이 항상 포함되며, 값이 없으면 `null`입니다.

### 에이전트가 사용할 수 있는 경로

키의 허용 범위와 무관하게, 아래 표의 경로만 `jpk_` 키로 호출할 수 있습니다. 표에 없는 경로(관리자·토론·LLM·키 관리·연구실 가입 관련 등)는 사용자 JWT 전용이며 키로 호출하면 403 `JWT_REQUIRED`가 반환됩니다.

| 범위 | 경로 |
| --- | --- |
| `account:read` | `GET /v1/me`, `GET /v1/auth/me` |
| `platform:read` | `GET /v1/tiers`, `GET /v1/workers`, `GET /v1/workers/{tier}/gpu/history`, `GET /v1/workspace-profiles`, `GET /v1/platform/stats`, `GET /v1/platform/queue-snapshot` |
| `jobs:read` | `GET /v1/jobs`, `GET /v1/jobs/{id}`, `GET /v1/jobs/{id}/gpu`, `GET /v1/jobs/{id}/gpu/history`, `GET /v1/jobs/{id}/log`, `GET /v1/jobs/{id}/results`, `GET /v1/jobs/{id}/results-zip` |
| `jobs:submit` | `POST /v1/jobs` |
| `jobs:cancel` | `POST /v1/jobs/{id}/cancel` |
| `queue:read` | `GET /v1/queue` |
| `queue:reorder` | `PUT /v1/queue/reorder` |
| `storage:read` | `GET /v1/storage`, `GET /v1/storage/objects`, `GET /v1/storage/objects/{key}/url` |
| `storage:write` | `POST /v1/storage/upload-url`, `POST /v1/storage/folders`, `POST /v1/storage/copy`, `POST /v1/storage/multipart/*` 등 |
| `storage:organize` | `POST /v1/storage/move`, `POST /v1/storage/rename` 등 |
| `storage:delete` | `DELETE /v1/storage/objects/{key}`, `POST /v1/storage/folders/delete` 등 |
| `lab:read` | `GET /v1/labs/me`, `GET /v1/labs/me/members`, `GET /v1/labs/me/jobs`, `GET /v1/labs/me/usage` |

인증 없이 누구나 호출할 수 있는 공개 경로는 `GET /v1/auth/config`와 `GET /v1/maintenance/status`뿐입니다.

## 3. 저장소 위치 지정 규칙

스토리지 API는 실제 버킷 이름 대신 **`scope`와 `folder` 두 값의 조합**으로 위치를 지정합니다. 조합은 네 가지뿐입니다.

| `scope` | `folder` | 용도 |
| --- | --- | --- |
| `shared` | `data` | 연구실 공유 데이터(작업 입력용) |
| `shared` | `result` | 연구실 공유 결과 |
| `private` | `data` | 내 전용 데이터 |
| `private` | `result` | 내 전용 결과 |

표 밖의 조합은 400 `INVALID_LOCATION`입니다. 파일 키(`key`, `prefix`)는 항상 이 논리 위치 기준의 **상대 경로**입니다.

```bash
# shared/data 아래 train/ 폴더의 파일 목록
curl --fail-with-body --get 'https://share.jedutools.io/v1/storage/objects' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY" \
  --data-urlencode 'scope=shared' \
  --data-urlencode 'folder=data' \
  --data-urlencode 'prefix=train/'
```

## 4. 파일 업로드와 다운로드

### 업로드 (storage:write)

업로드는 두 단계입니다. 먼저 업로드용 임시 주소를 발급받고, 그 주소로 파일 본문을 PUT 합니다.

```bash
# 1) 업로드 주소 발급 — content_length는 파일의 정확한 바이트 수
curl --fail-with-body 'https://share.jedutools.io/v1/storage/upload-url' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"scope":"shared","folder":"data","key":"train/sample.csv","content_length":1234}'
```

응답의 `url`과 `headers`를 그대로 사용해 PUT 합니다. **`headers`의 모든 항목을 빠짐없이 붙여야 합니다** — 특히 `x-amz-tagging`을 빠뜨리면 소유자 표시가 누락됩니다.

```bash
# 2) 발급받은 주소로 PUT (headers의 각 항목을 -H로 전달)
curl --fail-with-body -X PUT "$UPLOAD_URL" \
  -H 'x-amz-tagging: ...' \
  --data-binary @sample.csv
```

`content_length`가 단일 PUT 상한을 넘으면 400 `MUST_USE_MULTIPART`가 반환되며, 이때는 멀티파트 업로드(`POST /v1/storage/multipart/init` → `part` → `complete`)를 사용합니다.

### 다운로드 (storage:read)

```bash
curl --fail-with-body --get "https://share.jedutools.io/v1/storage/objects/train/sample.csv/url" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY" \
  --data-urlencode 'scope=shared' \
  --data-urlencode 'folder=data'
```

응답의 `url`은 만료되는 임시 다운로드 주소입니다. `expires_at`이 지나면 다시 발급받으세요.

## 5. 작업 제출·확인·취소

### 제출 (jobs:submit)

`POST /v1/jobs`는 `multipart/form-data`입니다. 코드 원본은 ZIP 파일(`artifact`) 또는 Git 주소(`git_url`) 중 **하나만** 지정합니다.

```bash
curl --fail-with-body 'https://share.jedutools.io/v1/jobs' \
  -H "Authorization: Bearer $JPUSHARE_API_KEY" \
  -F 'artifact=@code.zip' \
  -F 'command=python' \
  -F 'args=["main.py"]' \
  -F 'name=학습 실험' \
  -F 'work_type=training' \
  -F 'description=작은 데이터로 학습 확인' \
  -F 'tier=jpu-192' \
  -F 'timeout_seconds=3600' \
  -F 'channels=[{"name":"train","scope":"shared","folder":"data","prefix":"train/","size_gb":1}]'
```

- `args`와 `channels`는 JSON 문자열로 전달합니다.
- `channels`의 각 항목은 `name`(코드에서 `JOB_CHANNEL_<이름>` 환경 변수로 접근), `scope`, `folder`, `prefix`, `size_gb`를 가집니다.
- `tier`는 `GET /v1/tiers`로 현재 선택 가능한 값을 확인합니다. GPU 수는 tier가 결정하며 `num_gpus`는 무시됩니다.
- 응답은 `job_id`, `state`, `priority`, `tier`, `queue_position`, `warnings`를 포함합니다.
- 연구실 소속이 없으면 본문 검사 전에 403 `NO_LAB`이 반환됩니다.

### 상태·로그·결과 확인 (jobs:read)

```bash
# 상태 확인
curl --fail-with-body "https://share.jedutools.io/v1/jobs/$JOB_ID" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"

# 로그 (stdout 또는 stderr)
curl --fail-with-body "https://share.jedutools.io/v1/jobs/$JOB_ID/log?stream=stderr" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"

# 결과 파일 목록 — 각 항목의 url이 임시 다운로드 주소
curl --fail-with-body "https://share.jedutools.io/v1/jobs/$JOB_ID/results" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

에이전트가 작업 완료를 기다릴 때는 `GET /v1/jobs/{id}`의 `state`를 주기적으로 조회합니다. 화면의 **대기 중**은 `USER_QUEUE_WAIT`, `GLOBAL_QUEUE_WAIT`, `ESCALATION_WAIT`로 구분되고, **배정됨**은 `ASSIGNED`입니다. 실시간 로그가 필요하면 `log` 요청에 `follow=1`을 붙이면 SSE(`text/event-stream`)로 전달됩니다.

### 취소 (jobs:cancel)

```bash
curl --fail-with-body -X POST "https://share.jedutools.io/v1/jobs/$JOB_ID/cancel" \
  -H "Authorization: Bearer $JPUSHARE_API_KEY"
```

## 6. 오류 코드와 재시도

일반 오류 응답은 `code`, `error`, `message`를 포함하고, 작업 제출 검증 오류는 `status: "VALIDATION_FAILED"`와 `errors` 배열을 사용합니다. 에이전트는 HTTP 상태와 `code`를 함께 보고 분기하세요.

| 상태·코드 | 의미와 대응 |
| --- | --- |
| 401 | 키가 없거나 만료·폐기됨. `Authorization: Bearer jpk_...` 형식과 키 상태를 확인합니다. |
| 403 `JWT_REQUIRED` | 그 경로는 `jpk_` 키로 호출할 수 없습니다. 키 관리·관리자·LLM 경로는 브라우저 로그인 JWT가 필요합니다. |
| 403 `API_KEY_SCOPE_REQUIRED` | 키에 그 경로의 범위가 없습니다. 키를 폐기하고 필요한 범위를 포함해 다시 발급받습니다. |
| 403 `API_KEY_ROUTE_FORBIDDEN` | 분류되지 않은 경로입니다. 호출 경로와 메서드를 확인합니다. |
| 403 `NO_LAB` | 연구실 소속이 없어 작업 제출이 거절되었습니다. 계정의 연구실 참가 상태를 확인합니다. |
| 400 `INVALID_LOCATION` | `scope`/`folder` 조합이 잘못되었습니다. 네 가지 조합만 허용됩니다. |
| 400 `MUST_USE_MULTIPART` | 파일이 단일 PUT 상한을 넘습니다. 멀티파트 업로드로 전환합니다. |
| 429 | 요청이 너무 잦습니다. 응답의 재시도 대기 시간을 따르고 지수 백오프를 적용합니다. |
| 503 `SERVICE_MAINTENANCE` | 점검 중입니다. `GET /v1/maintenance/status`(공개)로 상태를 확인하고 종료 후 재시도합니다. |

키가 정상인데 특정 경로만 계속 거절되면, 그 경로가 키로 호출 가능한 경로인지 위 표에서 먼저 확인하세요. 범위는 발급 후에 바꿀 수 없으므로 부족한 범위는 새 키로 발급해야 합니다.

## 7. 주의할 것

- **LLM API 키(`sk-`)와 다릅니다.** `sk-` 키는 LLM 모델 조회·채팅 전용이며 작업·스토리지 API에는 사용할 수 없습니다. 반대로 `jpk_` 키는 LLM 경로를 호출할 수 없습니다.
- **키 관리는 JWT 전용입니다.** 키 발급·목록·폐기(`POST/GET/DELETE /v1/api-keys`)는 브라우저 로그인 세션에서만 가능하므로 에이전트가 자기 키를 관리할 수는 없습니다.
- **권한은 매 요청마다 다시 평가됩니다.** 키를 발급한 뒤 연구실 소속이나 역할이 바뀌면 다음 요청부터 새 권한이 적용됩니다.
- **만료를 미리 확인하세요.** 키는 최대 90일까지 유효하며 만료되면 401이 반환됩니다. 장기 실행 에이전트는 만료 전 재발급 절차를 운영자와 맞춰 두세요.

사람이 직접 호출하는 일반 API 사용법은 [API 사용법](/JPUShare/5API), 오류 대응은 [문제 해결](/JPUShare/6Troubleshooting)을 참고하세요.
